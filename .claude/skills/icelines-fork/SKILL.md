# icelines-fork

Fork files solve the agent fidelity problem: the agent gets one complete file
and does not work from a summary.

## Commands

```text
/icelines-fork 02
/icelines-fork 02 03
/icelines-fork --sync 02
```

## Procedure

1. Read `design/waves/PHASES.md`; select the active wave.
2. Read `design/waves/{active}/plans/pulse-{NN}.md` completely.
3. Extract `governing_roles` from frontmatter.
4. Resolve each role to `.roles/{role}.md`.
5. Write `design/waves/{active}/forks/pulse-{NN}.md`.

## Fork File Shape

```markdown
# Fork Context: Pulse NN - Title
# Wave: Backcheck the Phases

> Generated by /icelines-fork. Read completely before acting.

---

## Pulse Plan

{complete pulse plan verbatim}

---

## Governing Roles

### {role}

{complete .roles/{role}.md verbatim}

---

## Execution Contract

You are working in `C:\src\ICELINES`.

Run the gates listed in the pulse. For code changes, prefer focused tests first
and run broader gates at checkpoint boundaries. Check off gates in this fork
file as you complete them.
```

## Sync

`/icelines-fork --sync NN` reads checked gates from the fork and mirrors them
back to the source pulse plan.
