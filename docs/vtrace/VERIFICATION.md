# Verification Plan

## Scope

Repo or feature: `icelines` repo-baseline VTRACE adoption.

Verification asks whether implementation, docs, and commands satisfy the
requirements and code-rigor constraints. Validation asks whether the product
meets user and mission needs; this file names the repeatable checks and evidence
needed to prove those claims.

This docs-first VTRACE pass does not close implementation evidence by itself.
Rows stay `pending` until a command, fixture, snapshot, route/browser check,
demo transcript, dependency inspection, or explicit target-not-met result is
recorded. `REQ-DEP-001` and `REQ-LEAN-001` remain target requirements until
their dependency and lean-build evidence pass.

## Verification Rules

| Rule | Requirement |
|---|---|
| Evidence identity | Each evidence record must name the command or inspection, repo path, fixture/data source, result, and date or review entry. |
| Affected slices | Implementation PRs may use affected-slice commands only when they record why the slice covers all touched surfaces and invariants. |
| Surface claims | A surface claim closes only when ViewModel/envelope parity, source-state disclosure, active context, warnings, and empty/recovery states are checked where applicable. |
| Data claims | Data and upstream claims close only with fixtures or mocks for the relevant source, including failure and drift paths. |
| Public-copy claims | Report, export, web, and social/public text claims close only with snapshot or text review proving unsupported context is not implied. |
| Target claims | Standalone, FLETCH/SLICE removal, lean CLI, and named layout claims remain unmet target posture until their specific evidence passes. |
| Docs-only claims | VTRACE documentation changes may close with `proof check` and `git diff --check`, but that evidence does not close implementation rows. |
| Pointer semantics | Evidence pointers may include requirement, interface, or validation scenario IDs for context, but closure requires an `EVID-*` row or an explicit target-not-met row. |

## Status Semantics

| Status | Meaning | Allowed Use |
|---|---|---|
| pending | Evidence is required but has not been recorded for this VTRACE baseline. | Default for implementation, fixture, browser, parity, and snapshot rows in this docs-first pass. |
| target-not-met | The row is a valid target, but current repo state is known not to satisfy it. | Dependency-minimal, FLETCH/SLICE removal, lean CLI, and any future intentionally unmet target. |
| passed | Repeatable evidence has been recorded with command/artifact identity and reviewed. | Use only after the evidence row names the command, fixture, snapshot, route/browser check, inspection, or review entry. |
| blocked | Evidence cannot be collected because a prerequisite is absent or externally unavailable. | Use only with owner/revisit trigger in `REVIEW.md` or the gap ledger. |
| waived | A requirement or constraint is intentionally not enforced for a named scope. | Requires a waiver entry with owner, risk, exception rule, and revisit trigger. |
