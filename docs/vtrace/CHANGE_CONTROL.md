# Change Control

## Scope

Repo or feature: `icelines` repo-baseline VTRACE implementation.

Use this file when implementation changes requirement meaning, public interface
behavior, architecture boundaries, validation claims, verification methods,
accepted risks, code-rigor constraints, local-state schema, or dependency/build
posture.

Routine implementation that satisfies the existing controlled baseline does not
need a new change ID unless it changes one of those controlled meanings.

## Change-Control Rules

| Trigger | Required Action |
|---|---|
| Requirement wording or status changes | Add a `CHG-*` row and update `REQUIREMENTS.md`, `TRACE.md`, and `REVIEW.md`. |
| Public interface, URL state, local-state schema, report/export schema, or Cargo feature boundary changes | Add a `CHG-*` row and update `INTERFACES.md`, `TRACE.md`, and affected work package rows. |
| Architecture/design boundary changes | Add a `CHG-*` row and update `ARCHITECTURE.md` or `DESIGN.md` before closing implementation. |
| Validation or verification method changes | Add a `CHG-*` row and update `VALIDATION.md`, `VERIFICATION.md`, and `TRACE.md`. |
| Accepted risk or waiver changes | Add a `CHG-*` row and record owner, risk, exception rule, and revisit trigger in `REVIEW.md`. |
| Target-to-passed posture changes | Require evidence row identity before changing status. |
