# Trace Matrix

## Scope

Repo or feature: `icelines` repo-baseline VTRACE adoption.

This file is the end-to-end map from mission and CONOPS intent through
requirements, interfaces, architecture/design decisions, validation scenarios,
verification evidence, code-rigor constraints, and review closure. Status
describes evidence posture for this VTRACE baseline; it does not claim that
pending implementation behavior is already shipped or proven.

## Trace Rules

| Rule | Meaning |
|---|---|
| Requirement rows | Every `REQ-*` row must link to at least one CONOPS or mission need, one design or architecture element, a verification path, and evidence rows. |
| Evidence closure | Contextual `CON-*`, `IF-*`, `VAL-*`, `DES-*`, `CR-*`, and review IDs help explain the trace, but closure requires an `EVID-*` row or explicit `target-not-met` row. |
| Status alignment | Trace status uses the same evidence semantics as `VERIFICATION.md`: `pending`, `target-not-met`, `passed`, `blocked`, or `waived`. |
| Target honesty | Dependency/lean rows stay `target-not-met` until dependency and lean-build evidence passes; named layout rows stay pending target posture until layout schema and restore evidence pass. |
| Surface honesty | CLI, TUI, Web HTML, Web JSON, and report/export claims stay pending until parity, route/browser, snapshot, command, or demo evidence is recorded. |
| Static site posture | `icelines-site` and mkdocs remain deferred/historical for this VTRACE baseline; report/export artifacts remain active evidence surfaces. |
| Work package closure | `WP-*` rows are implementation planning and gate controls; closure still requires `EVID-*`, command, fixture, snapshot, route/browser, demo, blocked, waived, or target-not-met evidence. |
