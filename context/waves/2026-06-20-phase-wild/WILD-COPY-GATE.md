# Wild Line-Combination Product-Copy Gate

## Decision

The existing line-combination explorer copy is sufficient for a bounded
prepared-cache line-combination explorer claim.

This does not promote deployment advice, roster authority, or line-chemistry
causality. It only allows Phase Wild to claim that `/lines/explorer` and
`/api/v1/lines/explorer` are prepared-cache line-combination explorer surfaces
when a matching cache record exists.

## Accepted Claim

Line-combination explorer may be described as:

- an active-context prepared-cache line-combination explorer surface;
- backed by `AnalyticsCacheConsumerView` as `LineCombinationExplorer`;
- preserving source-state, quality, methodology, disclosures, non-claims, and
  metric evidence;
- rendering explicit unavailable state when the active cache record is missing;
- not recomputing analytics or fetching live data on read.

## Still Not Claimed

Line-combination explorer must not be described as:

- deployment advice or roster authority;
- line-chemistry causality or guaranteed chemistry;
- transaction, matchup, betting, or injury advice;
- autonomous coaching authority;
- prediction certainty;
- live analytics recomputation;
- a replacement for goalie, practice, postgame, or agent workflow evidence.

## Evidence

- The shared analytics-cache template states that it reads a named cache record,
  preserves source state, quality, methodology, disclosures, and non-claims, and
  does not recompute analytics or fetch live data.
- The line-combination JSON unavailable response tells users to build or restore
  the active line-combination analytics cache before using the explorer.
- Ready-route L2 coverage checks the report title, active cache key, metric
  rendering, JSON twin link, consumer kind, non-claim copy, and absence of
  guaranteed chemistry or deployment-recommendation copy.
- Missing-route L2 coverage checks explicit unavailable state and no cache
  directory creation on GET.
